# Dark Seal (Japan rev 4) — 초기 조사

작성 2026-10-04. 근거 이미지는 [evidence/](evidence/) (work/ 는 재생성 가능이라 핵심만 복사).

## 1. 하드웨어·ROM 적재 (FBNeo d_darkseal.cpp 로 확정)

| 항목 | 값 |
| --- | --- |
| CPU | 68000 @12MHz, 사운드 HuC6280 |
| 프로그램 ROM | `fz_04-4.j12`(상위)+`fz_01-4.h14`(하위) → 0x00000~0x3ffff, `fz_00-2.h12`(상위)+`fz_05-2.j14`(하위) → 0x40000~0x7ffff |
| **프로그램 스크램블** | 전 바이트 `BITSWAP08(b,7,1,5,4,3,2,6,0)` = **비트 1↔6 교환**. 해제본은 `work/prg_decoded.bin` (재생성: 아래 스크립트) |
| 문자(8×8) ROM | 부모 `fz_02.j1`(0x00000) + `fz_03.j2`(0x10000). 1비트 평면 4장: 평면0=0x00000, 1=0x10000, 2=0x08000, 3=0x18000 (타일당 평면 8바이트, MSB=왼쪽). 4096타일 |
| 16×16 ROM | mac-03(전경), mac-02(배경), mac-00/01(스프라이트) — 텍스트 무관 |
| 메모리 | RAM 0x100000~0x103fff, 스프라이트 0x120000, 팔레트 0x140000~0x141fff, pf_ram[2]/[3] 0x200000/0x202000, **pf_ram[0] 0x260000, pf_ram[1] 0x262000** (각 8KB) |
| 텍스트 레이어 색 | 레이어 1(pf_ram[1]) color base 0x000 → 팔레트 pal*16 + 픽셀값 (7=흰 230, 2=검정) |
| 스크롤 변수 | IRQ(0x18e~0x204)가 매 프레임 복사: **0x10031c/0x100320 → 0x2a0006/8 = 텍스트 레이어(칩0 pf2)**, 0x10038c-0x80/0x100390-0x80 → 0x240006/8 = 배경(칩1 pf2, pf_ram[3]), 0x10033c-0x100/0x100340-0x100 → 0x240002/4, 0x10035c-0x100/0x100360-0x100 → 0x2a0002/4 |
| 프롤로그 연출 | 설정 0xff54(텍스트 X=0x100), 루프 0xfe82~0xfee0 매 프레임 0xffac: 4프레임마다 X-1 → 0 정지 (왼→오 슬라이드). 배경은 0xfea0 블록이 4프레임마다 X+1 드리프트. 총 길이 countdown 0x10301c=0x7fa 프레임 |

## 2. 텍스트 레이어 (실측: Lua 덤프 frame 700/900)

- 프롤로그 표시 중 **0x262000 (pf_ram[1])** 에 429워드, 타일 0x200~0x3ff, 팔레트 0. 다른 PF RAM 엔 텍스트 없음.
- 타일맵 워드 = `pal<<12 | tile(12bit)`. **64열** 타일맵(64×64 셀, 8KB). 64열로 렌더하면 화면과 동일 ([evidence/pf1_262000_64col.png](evidence/pf1_262000_64col.png)).

## 3. 문자 타일 뱅크 (fz_02/03)

| 타일 범위 | 내용 |
| --- | --- |
| 0x20~0x7f | **ASCII = 타일 인덱스** (' '…'?', '@'…'_', 소문자) |
| 0x80~0xff | "UP"·아이콘·색 바 |
| 0x100~0x1ff | 그래픽 조각 |
| **0x200~0xfff** | **일본어 글리프**: 16×16 글자 1개 = 연속 타일 4개 `k(4의 배수)`: 화면 배치 TL=k+2, TR=k, BL=k+3, BR=k+1 (글리프 라이터 0x2892 로 확정). 8×8 가나(후리가나·소형 문구) 0x32c~0x35f 등 포함 |

비공백 타일 3,962/4,096. 스크립트가 실제 사용하는 16×16 글리프 base 는 **383종**(1,343회), 범위 0x200~0x9bc. 0xa00~0xfff 는 스크립트에서 미참조(용도 미확인 — 회수 후보지만 소비자 확인 전엔 비워 두지 않는다).

## 4. 텍스트 데이터 형식 (코드 0xffe2 / 0x1000c / 0x10028 디스어셈블로 확정)

### 4.1 글리프 스크립트 (라우틴 A, 0xffe2) — 일본어 본문

16비트 워드 열. a2 = 타일맵 시작(예: 0x262100 = 2행), a3 = 스크립트.

| 워드 | 의미 |
| --- | --- |
| `pal<<12 \| k` | 16×16 글리프 (sub 0x2892 가 4타일 기록), 커서 +2타일(16px) |
| `0x0000` | 빈 셀, 커서 +2타일 |
| `0xfffe` | 줄바꿈: a2 += 0x100 바이트 (=2타일 행=16px), 커서 복귀 |
| `0xffff` | 끝 |

세로쓰기는 데이터가 세로가 아니라 **타일맵 행 단위(가로)** 로 저장돼 있다: 프롤로그는 7열의 n번째 글자를 한 행에 `글리프,0,글리프,0,…` 로 늘어놓는다(글자 간격 32px, 그 사이가 후리가나 자리).

### 4.2 좌표·타일 쌍 (라우틴 B, 0x1000c)

`[타일맵 바이트 오프셋][워드]` 반복, `0xffff` 끝. 0x262000 기준. 후리가나·"(…伝承より)" 같은 8×8 소형 문구.

### 4.3 ASCII 문자열 (라우틴 C, 0x10028)

`[오프셋 워드][ASCII…][0x00 패딩(짝수 맞춤)][0xfe]` 반복, `0xffff` 끝. 각 바이트는 `d6`(팔레트 등 상위 비트) 과 OR 돼 타일 1개로 기록. 캐릭터 프로필 라벨·값 등.

## 6. 패치 범위에 대한 함의

- 일본어 글리프 타일은 **부모 세트 `darkseal.zip` 의 `fz_02.j1`/`fz_03.j2`** 에 있다 → 한글 글리프 삽입은 부모 ROM 수정. 스크립트는 클론 프로그램 ROM(`fz_0x`) 에 있다.
- 글리프 라이터가 4타일 고정이므로 **한글도 16×16 셀(2×2 타일)** 로 넣는 것이 코드 무수정 경로. 8×8 한글(Galmuri7)을 쓰려면 셀 안에 8×8 로 두거나(여백 큼) 2배 확대하거나, 라이터를 8×8 1타일 기록으로 바꾸는 훅이 필요 → 사람 결정 항목.
- 세로쓰기 유지 여부도 사람 결정. 가로로 바꾸려면 a2 시작·줄바꿈 폭은 그대로 두고 스크립트 데이터만 재배치하면 된다(라우틴 A 는 레이아웃을 데이터에서 읽는다).
